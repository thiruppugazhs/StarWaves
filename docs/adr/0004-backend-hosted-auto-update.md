# ADR 0004 — Backend-Hosted Auto-Update (Tauri Signed + APK Sideload + OTA)

## Status

Accepted

- Date: 2026-08-31
- Deciders: @susindran
- Tags: `updater`, `tauri`, `android`, `capgo`, `ota`

## Context

After adding build scripts (ADR 0003), installs still required manual APK/EXE reinstall. Product wants silent background checks with user-consent install, hosted on existing backend VM — not GitHub Releases. Desktop needs signed verification (supply-chain safety). Android today is sideloaded APK (no Play), so Play In-App Updates unavailable; we need a lightweight backend `/updates/check` + browser download fallback, with optional native `FileProvider` later. Additionally, OTA web-bundle patches (JS/CSS) without APK rebuild are desired (Capgo).

Constraints: backend is e2-micro (512M), 10r/s burst 60; public endpoints must be low-cache, CORS must allow `capacitor://` and `tauri://`; keys in env; `force:false` (no blocking) for now.

## Decision

Backend is source of truth: file-based manifests under `server/static/updates/` (bind-mounted `./server/static/updates:/app/static/updates`), served two ways:

- FastAPI `app.main:mount /updates → StaticFiles` + `app.api.routes.updates` (`GET /check`, `GET /latest.json`, `GET /android.json`, `GET /ota/latest.json`). Mount covers VM and dev; Nginx `location /updates/` proxies to `server_backend` (both `nginx.conf` and `default.backend.conf` with `burst 60`). CORS regex extended with `tauri://localhost`/`https://tauri.localhost`.
- Manifests: `latest.json` (Tauri `v1Compatible` with `platforms:{windows-x86_64:{url,sig}}`), `android.json` (`latestVersion/versionCode/url/sha256/size/force`), `bundles/latest.json` (OTA).

Desktop: `tauri-plugin-updater` + `tauri-plugin-process` (+ `dialog` existing). `tauri.conf.json` `bundle.createUpdaterArtifacts=v1Compatible`, `plugins.updater {pubkey, endpoints:[https://api.starwaves.susindran.in/api/v1/updates/latest.json], windows.installMode:passive}`. Private key from `TAURI_SIGNING_PRIVATE_KEY` env (or `~/.tauri/starwaves.key`), pubkey committed. Frontend `lib/desktopUpdater.js` wraps `fetchUpdateCheck` then Tauri plugin `check+downloadAndInstall+relaunch`; fallback to `window.open(url)`.

Android: `lib/androidUpdater.js` + `lib/updatesApi.js` (`/updates/check?platform=android`). Silent check only when `Capacitor.isNativePlatform()==android`; Settings → Updates allows manual check on any platform. Phase 1 UX = `window.open(apkUrl)` (no `REQUEST_INSTALL_PACKAGES` yet to avoid Play review friction); Phase 2 will add Kotlin `UpdaterPlugin` with `DownloadManager+FileProvider`. `android.json` generated by `build-android.ps1` (versionCode monotonic, writes `server/static/updates/android.json` + copies APK as `starwaves-<ver>.apk`).

OTA: `@capgo/capacitor-updater` optionalDependency; `lib/otaUpdater.js` checks `bundles/latest.json`, `notifyAppReady()` on launch, `CapacitorUpdater.download+set` when present, else stores `bundleId` and reloads. `build-ota.ps1/.sh` zips `website/dist` → `bundles/<id>.zip` + `latest.json`; `PUBLISH` scp to backend.

UI: `components/ui/UpdateBanner.jsx` (monochrome, `update-banner.css`) sticky top; `hooks/useAutoUpdater.js` startup delay 3.5s + 6h interval + visibility/resume triggers, dismiss per-version via `localStorage`; `pages/settings/UpdateSection.jsx` for manual check, integrated into `SettingPage`.

Version single-source `package.json.__APP_VERSION__` via vite `define`; `__APP_VERSION__` used by all checkers.

## Consequences

- **Positive:** No third-party hosting; same VM that serves API serves updater; signed desktop prevents tampering; Android/OTA reuse same backend; progressive (Phase 1 browser, Phase 2 native); all paths `/api/v1/updates/check` + static `/updates` low footprint.
- **Negative / Cost:** VM disk must retain 5 latest artifacts (pruning needed); Tauri key rotation requires app update via old key; OTA zip full bundle (no delta) → 2-5MB each; `capgo` not yet installed in CI (optional).
- **Follow-up:** Prune job `retain 5 newest` cron; add native `UpdaterPlugin` Kotlin file; GH Actions `release.yml` to build + scp; `UPDATER_SECRET` guard for OTA upload endpoint; metrics `ai_usage`-like for update installs.

## Alternatives Considered

| Alternative | Why rejected |
|-------------|--------------|
| GitHub Releases for `latest.json` | Rejected per decision — backend preferred; GH could be fallback remote |
| Capgo Cloud OTA | Desired but self-hosted backend keeps data on VM; Capgo plugin still usable with self URL |
| Play In-App Updates | Requires Play listing; deferred until publishing |
| `window.open` only (no API check) | No gating/force/staged rollout; API enables future canary |
